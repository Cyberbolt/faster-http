# 开发标准规范

## 开发规范

### 代码质量要求
- 编写生产级别代码，严格按照最佳实践

### 项目管理
- 使用 `uv` 管理项目依赖和环境
- 执行模块：`uv run -m` 替代 `python -m`
- 添加依赖：`uv add` 添加生产依赖，`uv add xxx --dev` 添加开发依赖
- 不熟悉 uv 用法时，使用 context7 查询文档

### 代码检查与编译
- Python 代码修改后用 `ruff` 检查代码质量
- Rust 代码修改后运行 `uv run maturin develop --release` 重新编译

### 临时代码执行
- 验证想法时使用：`uv run python -c "代码内容"`
- **严禁在项目根目录创建临时文件**

### 任务执行限制
- **禁止运行任何无限阻塞的任务**（如 server 等）
- 所有长时间运行的任务必须添加 `timeout` 限制

### CI/CD 配置
- `benchmarks` 目录不参与 CI/CD 流程

## 测试规范

### 测试覆盖与结构
- 测试代码必须覆盖项目全部功能
- 测试文件统一放置在项目根目录的 `tests/` 目录
- `tests/` 目录按功能模块划分清晰的子目录结构
- 创建单元测试和集成测试两个层级

### 兼容性测试流程
- 先用 `httpx` 实现测试
- 再用 `faster-http` 运行相同测试进行对比
- 如发现 `faster-http` 接口不兼容 `httpx`，优先修改源码适配
- `faster-http` 不得实现 `httpx` 不支持的接口

### 测试独立性
- **测试不得依赖任何外部网站或服务**
- 所有测试必须能在内部环境完全运行

### 测试代码管理
- 新建测试时复用现有测试结构和代码，避免重复
- 代码更新后及时更新对应测试，删除过时测试
- 保持测试逻辑完备且精简，无冗余代码
- **严禁在项目根目录放置测试文件**

### 测试执行
- 并发运行全部测试：`uv run -m pytest tests/ -n auto`
- 测试通过率必须保持 100%
- 测试失败时立即排查代码实现或测试代码问题并修复

## 性能测试规范

### 测试环境
- 性能测试代码位于 `benchmarks/` 目录
- 测试服务地址：`http://nginx:21000`（已预配置，请勿修改）
- **普通功能测试禁止访问此服务**

### 执行命令
```bash
sh scripts/auto_taskset.sh "timeout 60s uv run -m benchmarks.faster_http_test"
```

### 执行要求
- 使用 `scripts/auto_taskset.sh` 限制 CPU 核心数确保测试公平性
- 必须添加 `timeout` 避免进程阻塞
- 性能测试与功能测试严格分离
