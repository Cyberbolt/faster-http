# Git 规范

## Git Commit

消息模板必须包含准确且信息丰富的主题行，以及必要的正文和页脚。

以下是提交消息模板：
<type>(<scope>): <subject>

// 空行
<body>

// 空行
<footer>

### 提交消息生成规则：

1. **标题**（必填）：包含以下内容：
   - `<type>`：从以下枚举中选择一个：
     - feat: 新功能
     - fix: 修复 Bug
     - docs: 文档更新
     - style: 格式调整（不影响代码执行的更改）
     - refactor: 重构（既不是新增功能也不是修复 Bug 的代码更改）
     - test: 添加测试
     - chore: 修改构建过程或辅助工具的变更
     - perf: 性能优化（提升代码运行效率的改动）
     - build: 构建系统或外部依赖项的改动（例如升级 npm 包、修改 Gradle 配置等）
     - ci: 持续集成配置的变更（例如 GitHub Actions 配置、Jenkins 配置等）
     - revert: 回滚提交（撤销之前的某次提交）
     - deps: 依赖更新（升级或降级依赖库版本）
     - security: 安全修复（修复安全漏洞或风险）
     - ux: 用户体验优化（不属于新功能，但对 UI/UX 有改进）
     - hotfix: 紧急修复（快速修复线上 Bug 或重大问题）
   - `<scope>`：具体影响范围或模块名称（如 API、UI、数据库等）。
   - `<subject>`：简要总结本次变更内容（不超过 72 字符）。

2. **正文**（可选）：详细描述提交内容。
   - **如果本次提交改变很大或很重要**，请：
     - 使用段落或项目符号详细描述变更点及其影响，保持单行不超过 72 字符。
     - 解释变更的背景、动机及可能的副作用。
   - **如果本次提交改变很小或不重要**，请：
     - 不描述变更内容

3. **页脚**（可选）：用于补充提交的关联信息，例如：
   - 关联 Issue，如 "Close #1234"。
   - 标注 Breaking Change，并说明变更内容。
   - 描述对其他模块的依赖影响。

4. **变更大小判断**：
   - 在生成提交信息前，明确声明本次提交是“改变很大或很重要”还是“改变很小或不重要”，并据此生成对应的提交信息内容。

5. **避免多余提交**：
   - 提交内容应尽可能清晰和完整，避免将多个小改动分散为多条提交，确保易于维护。

6. **其他注意事项**：
   - 如果 `git diff --cached` 无暂存更改，应提示用户无需提交。
   - 如果更改较大，应生成适当的概览，并提示用户是否需要拆分提交。
   - 确保所有内容对齐，避免换行或长度超限影响美观。
